# Goal

Now that I have pfSense and Pi-hole running, I want to set up a VPN in order to access the lab from outside the house without exposing anything directly to the internet. To do this I have decided to use Wireguard because it is lightweight and relatively easy to configure.

**Specific Goal:** Connect my phone to a WireGuard tunnel ending at pfSense with firewall rules scoping exactly what the VPN client subnet can reach (lab subnet, Proxmox, etc.)

## Steps

### Set up port forwarding

In order to connect to my home network while not being on the same Wi-Fi, I have to open a dedicated port on my router for VPN traffic, and forward that traffic to pfSense. This process is heavily dependent on what kind of router you have. For my router, it is simply done through an app.

### Installing Wireguard

By default, pfSense comes with OpenVPN, which is just another VPN tool. To install Wireguard, navigate to `System > Package Manager > Available Packages`, and search for and install Wireguard.

### Creating the tunnel

Once the WireGuard package is installed on pfSense, it will show up in the VPN section. To create a tunnel, navigate to: `VPN > WireGuard > Tunnels > Add Tunnel`. Here is how I configured my tunnel:

* **Listen Port:** `51820` (default port)
* **Interface Keys:** You can either use your own keys or generate them
* **Interface Address:** `10.10.10.1/24` (This is pfSense's own address inside the VPN subnet)

Note: The subnet for the VPN client (`10.10.10.0/24`) was manually picked because it's not assigned to anything else. This just ensures that there are no collisions down the road.

### Assigning the interface

In order to create firewall rules specific to VPN traffic, I had to enable the interface from `Interfaces > Assignments > tun_wg0`. Once enabled, I renamed it and made sure the IPv4 configuration type is set to static.

### Add peer(s)

To allow a device to connect using the VPN, you must add the device as a peer and configure it from both the client and server sides. To add a new one go to `VPN > WireGuard > Peers > Add Peer`. From here, I added my phone and gave it an IP on the VPN subnet (`10.10.10.3/32`).

Each device that you want to add will generate its own keypair locally in the app. For mobile devices specifically, **Dynamic Endpoint** must be checked since its IP will change depending on what cell tower or network it's connected to.

### Client-side Config (Phone)

To allow my phone to send through the firewall, I set myself up as a new peer.

```
[Interface]
PrivateKey = <auto-generated>
Address = 10.10.10.3/32

[Peer]
PublicKey = <pfSense's public tunnel key>
AllowedIPs = 10.0.0.50/32, 192.168.10.0/24
Endpoint = <home public IP>:51820
PersistentKeepalive = 25
```

`AllowedIPs` is deliberately scoped to **only** allow traffic to specific lab devices like Proxmox, VMs, and Pi-hole through the tunnel instead of routing all traffic through pfSense.

**Optional:** I decided not to set up Pi-hole as the DNS server for the VPN because it was complaining about resource usage

### Firewall rules

As of right now, my phone can successfully reach pfSense via the VPN, but since there are no firewall rules configured, all traffic gets dropped. To fix this, I want to allow access to pfSense, as well as Proxmox.

Navigate to `Firewall > Rules > WIREGUARDINTERFACE`, and add two new rules.

| Destination | Port | Protocol | Purpose |
|---|---|---|---|
| `10.0.0.50/32` | 8006 | TCP | Proxmox Web UI |
| `192.168.10.0/24` | any | any | Reach VMs, pfSense GUI, etc. |

Once these rules have been created, a separate rule on the WAN interface needs to be made to allow inbound UDP traffic on port 51820. 

### Testing

Once all of these steps have been completed, I turned off my phone's Wi-Fi to force a cellular connection, and I enabled the VPN. Once I verified that the handshake was successful in the logs, I attempted to access both the Proxmox web GUI, and the pfSense web GUI, both of which were successful.

# Troubleshooting

[**~/Section/Firewall Rules**](#firewall-rules)

* **Issue:** Port forwarding for Wireguard (UDP 51820 --> pfSense WAN) was setup and verified, but handshakes never completed. Using `tcpdump`, I verified that pfSense *was* receiving the handshake request, but not sending a reply.
* **Solution:** The WAN *allow* was not properly set up and needed to be configured.
---
* **Issue:** Even after creating the WAN rule, triple-checking public keys/addresses, and fully rebooting pfSense, the handshake was still failing.
* **Solution:** Fixed by regenerating a new keypair for the server-side tunnel and updated the peer config on the client side. Note: I'm not sure what the root cause of this was, my best guess is that the keys got out of sync at some point
